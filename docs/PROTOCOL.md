# Protocol

All formats are defined once in `crates/sphinx-protocol`. Golden vectors in
`fixtures/golden/messages.json` pin them; the protocol, contract and CLI test
suites all read that file.

## Hashes

`Hash32` is SHA-256 written as exactly 64 lowercase hex characters.
Uppercase is rejected so that one value has one text form.

- **suite hash**: SHA-256 of the suite file's exact bytes (no canonicalisation),
  so anyone can recompute it with `shasum -a 256`. `sphinx suite hash <file>`
  prints it.
- **code hash** and **reference hash**: SHA-256 of the exact source bytes.

## Signed messages

ASCII, `:`-separated, no trailing newline. Every field is an account id, a
decimal integer, a bool, a runtime id or lowercase hex. None of these can
contain `:`, so the encoding is unambiguous.

```
sphinx:v1:suite-check:{contract}:{job_id}:{valid}:{suite_hash}:{ref_solution_hash}:{nonce}
sphinx:v1:score:{contract}:{job_id}:{sub_id}:{runtime}:{passed}:{total}:{suite_hash}:{code_hash}:{nonce}
```

- `contract` binds a result to one escrow account.
- `nonce` is generated by the contract from the block's random seed for each
  suite commit and each submission, so a signature cannot be replayed on
  another job, another submission, or the same account name on another
  network. (A dedicated chain id is not used: NEAR's `chain_id()` host
  function, NEP-638, is still a draft.)
- The two message kinds have different prefixes, so a suite-check signature
  can never be used as a score.

The signature is ed25519 (RFC 8032) over those bytes, 64 bytes, hex-encoded.

## JSON shapes posted to the contract

```jsonc
// record_suite_check
{"check": {"contract": "...", "job_id": "7", "valid": true,
           "suite_hash": "<64 hex>", "ref_solution_hash": "<64 hex>", "nonce": "<64 hex>"},
 "signature_hex": "<128 hex>"}

// record_score
{"score": {"contract": "...", "job_id": "7", "sub_id": 3, "runtime": "js-boa/1",
           "passed": 12, "total": 12, "suite_hash": "...", "code_hash": "...", "nonce": "..."},
 "signature_hex": "<128 hex>"}
```

`job_id` is a decimal string (u64 is not safe in JavaScript numbers). Unknown
fields are rejected.

## Suite format (`sphinx.suite/1`)

```json
{"version": 1, "runtime": "js-boa/1", "entry": "fib",
 "tests": [{"args": [10], "expected": 55}]}
```

Intake rules (checked by the grader and by `sphinx suite check`):

| Rule | Limit | Error |
|---|---|---|
| file size | 256 KiB | `SPHINX_E_GRADER_SUITE_TOO_LARGE` |
| tests | 1 to 32 | `SPHINX_E_GRADER_SUITE_EMPTY`, `..._TOO_MANY_TESTS` |
| value nesting | 32 levels | `SPHINX_E_GRADER_SUITE_VALUE_TOO_DEEP` |
| numbers | finite; integers within ±(2^53 − 1) | `SPHINX_E_GRADER_SUITE_UNREPRESENTABLE` |
| object keys | no `__proto__` | `SPHINX_E_GRADER_SUITE_UNREPRESENTABLE` |
| entry | plain identifier, not a keyword or built-in | `SPHINX_E_GRADER_ENTRY_INVALID`, `..._RESERVED` |

Errors never quote suite contents.

A test passes when the entry function, called with `args`, returns a value equal
to `expected` under JSON equality in which numbers compare by value (`1 == 1.0`),
object key order is ignored, and array order matters.

## Grader request and response (`sphinx.grader/1`)

One JSON request on stdin, one JSON response on stdout.

```jsonc
// grade
{"op": "grade", "schema": "sphinx.grader/1", "contract": "...", "job_id": "7", "sub_id": 3,
 "nonce": "<64 hex>", "suite": "<suite file text>", "expected_suite_hash": "<64 hex>",
 "submission": "<source>", "expected_code_hash": "<64 hex>", "epoch_ms": 0}
// validate: same, with "reference" and "expected_ref_hash" instead of submission fields, no sub_id
```

### Hidden inputs

On the network, `suite` and `reference` are left out of the request. The
grader then reads them from the environment variables `SUITE` and `REFERENCE`,
which OutLayer fills from the buyer's secret `sphinx-job-{job_id}` only when
the run is this exact grader build started by the account named in the
secret's access rule. The `expected_*_hash` fields are still required, and the
grader still hashes what it actually ran. If a value is missing, the grader
fails closed with `SPHINX_E_GRADER_HIDDEN_INPUT_MISSING` and signs nothing.

The secret is encrypted on the buyer's machine (`sphinx suite store`, or the MCP
`sphinx_post_job` tool) with OutLayer's keystore scheme: X25519 key agreement
with the keystore key for (grader build, buyer, profile), HKDF-SHA256 with
info `outlayer-keystore-v1`, and ChaCha20-Poly1305. Only ciphertext leaves
the buyer's machine. Its access rule is:

```json
{"Logic": {"operator": "And", "conditions": [
  {"Whitelist": {"accounts": ["<caller>"]}},
  {"WasmHash": {"hash": "<grader sha256>"}},
  {"Predecessor": {"condition": {"Whitelist": {"accounts": ["<caller>"]}}}}
]}}
```

The ciphertext is sent as `base64(0x01 | ephemeral X25519 public key (32) |
nonce (12) | ciphertext | tag (16))`.

### Encrypted submissions and chain binding

Transaction arguments are public, so on the network the submission is sent as
`submission_box` instead of `submission`: the code encrypted to the grader's box
key with the same construction as the hidden suite, but HKDF info
`sphinx:v1:box:submission`. The grader opens it, then hashes the plaintext
and compares it to `expected_code_hash` as before.

```jsonc
{"op": "grade", "schema": "sphinx.grader/1", "contract": "...", "job_id": "7", "sub_id": 3,
 "nonce": "<64 hex>", "expected_suite_hash": "<64 hex>",
 "submission_box": "<base64 box>", "expected_code_hash": "<64 hex>", "epoch_ms": 0}
```

The box key is X25519. Inside the enclave its secret is
HKDF-SHA256(ikm = `mac("box", none, "sphinx:v1:kdf:box-v1")`, info
`sphinx box v1`), where `mac` is OutLayer's `encryption-keys` HMAC under a key
bound to the grader build and caller (`"encryption_keys":[{"path":"box","bind":"wasm"}]`).
The secret never leaves the run. `{"op": "identity", "schema": "sphinx.grader/1"}`
answers `{"schema", "ok": true, "op": "identity", "grader_version", "kind",
"signing_public_key": "<64 hex>", "box_public_key": "<64 hex>"}`; the owner
registers both with `set_grader_key(public_key_hex, box_public_key_hex, mode,
wasm_sha256, attestation_ref)`, and each job keeps the key it was committed
with, so the relayer encrypts each submission to `job.commit.grader.box_public_key`.

The enclave build also refuses requests the chain did not ask for:

- inline `suite`, `reference` or `submission`: `SPHINX_E_GRADER_INLINE_INPUT_REFUSED`;
- a buyer's secret whose `CONTRACT` and `JOB_ID` are not the request's
  (`sphinx suite store` writes both next to `SUITE` and `REFERENCE`):
  `SPHINX_E_GRADER_SUITE_NOT_FOR_JOB`;
- `grade` unless `get_job` on `contract` is `Open` with `commit.suite_hash` equal
  to `expected_suite_hash`, and `get_submission` is `Pending` with the same
  `code_hash` and `nonce`; `validate` unless `get_job` is `Committed` with the
  same `suite_hash`, `ref_solution_hash` and `suite_check_nonce`:
  `SPHINX_E_GRADER_NOT_ON_CHAIN`. The views are read from final blocks through
  OutLayer's NEAR RPC host functions; the manifest allows no outbound network.

A box that does not open is `SPHINX_E_GRADER_BOX_UNREADABLE`. Local builds keep
accepting inline inputs and skip the chain checks.

Success:

```jsonc
{"schema": "sphinx.grader/1", "ok": true, "op": "grade", "grader_version": "0.1.0",
 "runtime": "js-boa/1", "result": { /* the score or suite check */ },
 "message": "sphinx:v1:score:...", "signature": "<128 hex>|null",
 "signer": {"kind": "outlayer|dev", "public_key": "<64 hex>"} | null,
 "preflight": {"code": "SPHINX_E_CODE_SYNTAX", "message": "..."}  // only when the submission could not load
}
```

Failure: `{"schema", "ok": false, "op", "job_id", "nonce", "grader_version", "error": ErrorReport}`
with `ErrorReport` as in [ERRORS.md](ERRORS.md). The process exits 0 whenever a
response was written.

A submission that does not load, or does not define the entry function, still
receives a signed `0/N` score with a `preflight` explanation. On-chain that is
a failed attempt, so agents should run `sphinx check` first.
