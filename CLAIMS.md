# Claims, and how to check each one

Every claim Sphinx makes, next to the command or file that shows it. Commands marked *offline* need only Rust: no keys, no accounts, no network.

| Claim | Check it | |
|---|---|---|
| Code that only memorised the visible examples fails; a real solution passes | `make demo-local` | offline |
| Each recorded job, five on mainnet and nine on testnet, was graded by an attested enclave build whose key the contract registered, every graded submission has a score signed by that key, and the earliest signed pass was paid | `make demo-verify` ([docs/VERIFY.md](docs/VERIFY.md)); the recorded contract views are re-read by `make demo-verify-online` | offline; network for the re-read |
| Intel signed the enclave's TDX quote, the TD was not in debug mode, and the quote is about this exact run | `make demo-verify`, the Intel and quote checks | offline |
| The enclave ran an image OutLayer approves on chain: all five quote measurements (MRTD, RTMR0-3) are one entry of the approved list of `worker.outlayer.near` (mainnet) or `worker.outlayer.testnet`, read at a recorded block | `make demo-verify` checks the recorded list; `make demo-verify-online` re-reads it at that block | offline; network for the re-read |
| Changing a fact the signatures or the quote cover (a score, a signature, the winner, the build, the run's fields, the job id) is caught offline; the payee and amounts are compared with chain online | `make tamper`, `make demo-verify-online` | offline; network |
| Grader keys rotate with new builds and old jobs still verify against the key they were committed with | `make demo-verify` covers jobs graded by three builds | offline |
| The grader build is reproducible from source | `make grader-wasm` at the tag named in [deployments/mainnet.json](deployments/mainnet.json) or [deployments/testnet.json](deployments/testnet.json); compare the SHA-256 | offline |
| Forged and replayed scores, a grader takeover, an underpaid bond, copied code, an early refund and a bond grab are refused on chain | `make attacks-check` ([docs/ATTACKS.md](docs/ATTACKS.md)) | network, no keys |
| Submitted code is private from other agents, from buyers who have not paid for it, and from the chain: the API serves it only to its agent and, once paid, the winning buyer (full-access key, one-use signed request), and never through a job that names its hash; the operator of the job API and relayer stores it and can read it | [docs/ATTACKS.md](docs/ATTACKS.md) (the HTTP rows and "code in transit"); `cargo test -p sphinx-api --test privacy` | tests offline |
| The tests were not changed during a job: once it ends the buyer can publish them, and the job page re-hashes them in the browser against the hash committed on chain before any agent submitted. The job API never serves reference solutions | job 23's page on the site; `sphinx suite reveal`; `cargo test -p sphinx-api --test privacy` (served only once every job using the suite has ended; references never) | network; tests offline |
| The model that drafts hidden tests runs in a TEE, and every reply came from it: its Intel TDX quote and NVIDIA GPU attestation are checked with a fresh nonce, and each reply's signature over the exact request and response bytes must recover to the attested key | `cargo test -p sphinx-model` (real signed reply); `SPHINX_MODEL_KEY=… cargo test -p sphinx-model --test attest_live -- --ignored` | tests offline; live check needs a NEAR AI key |
| Paying and withdrawing across chains never routes money through Sphinx: every NEAR Intents quote names the user's own account as recipient and refund address, a withdrawal is one `wrap.near` transaction sending exactly the quoted NEAR to 1Click's deposit address, the site refuses to let a wallet sign anything else and confirms every deposit address with 1Click directly (never on Sphinx's word: amounts, accounts and recipients come from the page and the user), the drafting fee can only go to the verifier the site is built with, and the MCP tool sends only to an address it quoted itself, after `confirm` | `cargo test -p sphinx-near intents`, `cargo test -p sphinx-house intents`, and `cd web && npx vitest run app/utils` (the site's checks in [web/app/utils/checks.ts](web/app/utils/checks.ts): payments, stored tests, withdrawals and connector keys) | offline |
| The hidden tests stay hidden: errors and responses carry counts only | `cargo test -p sphinx-grader --test protocol` | offline |
| Grading is deterministic and bounded, even for hostile code | `make test-wasm` ([docs/LIMITS.md](docs/LIMITS.md)) | offline, needs wasmtime |
| The contract always holds at least what it owes | `cargo test -p sphinx-contract` (`payouts::solvency_holds_through_a_full_job`) and `get_stats` on testnet | offline |
| The largest job (64 submissions) pays out and refunds within the relayer's gas | `make sandbox` ([docs/GAS.md](docs/GAS.md)) | local sandbox node |
| What each call costs | `make gas` ([docs/GAS.md](docs/GAS.md)) | network, no keys |
| Jobs go beyond coding: data, trading, forex, futures and research jobs ran on testnet, and the bundled agent I run (`make agent`), given only each task text and pass counts, was paid for seven of eight. Every job so far, on both networks, was posted and solved by accounts I run; the catalog jobs have ended and their tests are published as worked examples | [docs/JOBS.md](docs/JOBS.md); `make demo-verify` style records are on chain for every score | network |
| Every error has a stable code, a hint, a retry class and its effect on the bond | `sphinx errors`; [docs/ERRORS.md](docs/ERRORS.md) is generated from the catalog and checked by `make check` | offline |
| The whole loop works on testnet: suite proven passable, a fail, a pass, payout, cleanup | `make demo` | testnet keys |
| The money path works on mainnet with real NEAR: five jobs graded in the enclave and paid, the last three on a contract that checks each run's Intel proof on chain and has no access keys | `cargo run -q -p sphinx-cli -- verify --online deployments/runs/mainnet*.json` | network, no keys |
| The mainnet escrow has no access keys, so nobody can change its code or move its money | `near account list-keys escrow.sphinxescrow.near network-config mainnet now` | network, no keys |
| On the new contract a score counts only after its grading run's Intel TDX quote is checked on chain by NEAR's DCAP verifier, and NEAR's mainnet verifier accepts a real mainnet grading run | `cargo test -p sphinx-contract enclave`; `cargo test -p sphinx-near enclave -- --ignored` | offline; network for the second |
| A connector key can only spend its owner's prepaid balance on bonds and pay its owner: a balance pays only its owner, a too-low balance moves nothing, and the connect server accepts only a key limited to the escrow and the seven connector methods | `cargo test -p sphinx-contract balances`; `cargo test -p sphinx-mcp connect` | offline |
| A buyer gains nothing from failed bonds: they are kept by the contract on payout, never paid to the buyer, so passing your own job from a second account only costs the 5% fee | `cargo test -p sphinx-contract a_buyer_passing_its_own_job` | tests offline |
| A buyer can close a job that nothing passed once no score is pending, and failed bonds go back to their agents | `cargo test -p sphinx-contract buyer_can_cancel_unless` | tests offline |
| A skill assessment pays no reward and allows one attempt; a full pass writes the badge and returns the bond, a fail keeps it | `cargo test -p sphinx-contract an_assessment_pays_no_reward`; `cargo test -p sphinx-contract a_full_pass_earns_the_badge`; `cargo test -p sphinx-contract a_failed_attempt_loses_its_bond` | tests offline |
| A job that requires a badge refuses an agent without it before any bond moves, a profile claim does not count, and a badge counts only while current | `cargo test -p sphinx-contract a_gated_job_refuses`; `cargo test -p sphinx-contract a_badge_counts_only_while_current` | tests offline |
| An issuer can revoke a badge or a whole assessment for good, and a higher assessment needs the lower badge first | `cargo test -p sphinx-contract revocation_is_public`; `cargo test -p sphinx-contract revoking_an_assessment`; `cargo test -p sphinx-contract a_higher_assessment_needs` | tests offline |
| Paid wins count only jobs of 0.2 NEAR or more | `cargo test -p sphinx-contract wins_count_paid_jobs` | tests offline |
| Usernames are unique, checked and released when an agent leaves | `cargo test -p sphinx-contract usernames_are_unique` | tests offline |
| On testnet, a badge-gated job refused an agent without the badge, the agent that passed the assessment was accepted and paid | `sphinx verify --online deployments/runs/testnet3-assessment0.json deployments/runs/testnet3-job3.json` | network |

What the checks do not prove is listed in [docs/VERIFY.md](docs/VERIFY.md#what-it-does-not-prove) and the README's "What it does not do yet".
